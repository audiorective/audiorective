# @audiorective/clock V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `@audiorective/clock` V1 — the temporal pillar: transport anchor + tempo curve + look-ahead tick loop, with stateless rulers (grid scheduling + reactive `current` for visuals), miss detection, `generation`, and basic seek.

**Architecture:** Core is three pieces of state — the audio clock (borrowed), a transport anchor `{beatAtAnchor, timeAtAnchor}`, and a `TempoParam` event list; beat position is always derived (`beat(t) = beatAtAnchor + ∫ bpm/60`). `Clock` owns the worker tick loop and transport; `Timeline` owns the anchor + curve (all beat↔time conversion); rulers are stateless readers registered on the Timeline. Everything schedulable takes absolute audio-clock seconds.

**Tech Stack:** TypeScript, `@audiorective/core` (`Param`), alien-signals, tsdown, vitest browser mode (chromium). The clock core is deterministic — most tests inject a fake `{ currentTime }` and a manual tick source; only one integration test uses a real `AudioContext`.

**Spec:** `docs/superpowers/specs/2026-07-04-clock-design.md` (read it first — it is the contract; this plan only adds implementation decisions)

**Branch:** `claude/clock-package-design-check-vwg7hc`. Run tests with `pnpm --filter @audiorective/clock test -- --run`, a single file with `pnpm --filter @audiorective/clock test -- --run tests/<file>`.

## Implementation decisions this plan adds to the spec

These resolve the spec's "implementation detail" points; deviate only with good reason and record why:

1. **Time source is structural.** `Timeline` takes `audioContext: { currentTime: number }` — satisfied by `BaseAudioContext` and by a fake in tests. The clock never calls any other context member.
2. **Conversions while not playing** answer "as if the transport resumed now": `beatToTime` substitutes `now` for `timeAtAnchor`; `timeToBeat` returns the frozen `beatAtAnchor`. (Spec: "conversions are valid even while paused.")
3. **`transport.position` (and `LinearTimeRuler.seconds`)** = pause-aware played seconds, accumulated at anchor writes. `seek(beat)` sets it to `beat × 60 / bpm.valueAtTime(now)` — exact under constant tempo (the V1 common case), approximate under step-tempo history; documented, made exact by the V3 tempo map.
4. **Beats-per-bar** = `numerator × 4 / denominator` (the axis unit is a quarter note by Link/MIDI convention, per spec).
5. **Ruler interface** has a window form and a point form:
   `read(window, timeline): TWindow` (data + `grid()`/`spans`) and `at(beat, timeline): TPoint` (data only, feeds `current`).
6. **Grid points** are generated by integer step index — `k·step + origin` for integer `k`, half-open `[startBeat, endBeat)` — never by accumulation, so no float drift; `index = k` (position-derived).
7. **Tick sources are pluggable and exported**: `WorkerTickSource` (default; inline Blob worker running `setInterval`), `IntervalTickSource` (fallback when `Worker` is unavailable), `ManualTickSource` (tests drive ticks by hand).
8. **`TempoParam` scheduling in V1 throws on ramp methods** (`linearRampToValueAtTime`, `exponentialRampToValueAtTime` → "V2") rather than silently degrading; `cancelAndHoldAtTime(t)` under step-only events ≡ `cancelScheduledValues(t)` + `setValueAtTime(valueAt(t), t)`.
9. **Convenience conversions** (`nextBarTime()` etc.) stay out of V1 — spec open question 4 remains open.

## Task 2: TempoCurve (internal event list + integrals)

**Files:** `src/TempoCurve.ts`, `tests/tempoCurve.test.ts`

The correctness kernel. Pure, no time source, no signals. V1 events are steps only:

```ts
interface TempoEvent { time: number; value: number }   // sorted by time

class TempoCurve {
  constructor(initialBpm: number)                       // implicit event at time 0
  setValueAtTime(value: number, time: number): void     // insert sorted; replace exact-time duplicate
  cancelScheduledValues(time: number): void             // drop events with event.time >= time
  cancelAndHoldAtTime(time: number): void               // cancel >= time, then setValueAtTime(valueAt(time), time)
  valueAt(time: number): number                         // step lookup (binary search, last event <= time)
  beatsBetween(t0: number, t1: number): number          // Σ per segment: (segEnd − segStart) × value / 60
  timeToAdvance(fromTime: number, deltaBeats: number): number
                                                        // inverse: walk segments consuming beats; returns seconds
}
```

- [ ] Write tests first: constant curve (beatsBetween/timeToAdvance are linear); step at t=10 splits the integral correctly; `timeToAdvance` is the exact inverse of `beatsBetween` across segment boundaries; cancel semantics; `valueAt` at exact event times (event takes effect **at** its time); validation throws `RangeError` on non-finite or `<= 0` bpm; `deltaBeats = 0` → `0`.
- [ ] Implement. Keep segment walk O(log n + segments in range).
- [ ] Verify: `pnpm --filter @audiorective/clock test -- --run tests/tempoCurve.test.ts`

## Task 4: Timeline (anchor + conversions + generation)

**Files:** `src/Timeline.ts`, `src/types.ts`, `tests/timeline.test.ts`

- [ ] Constructor `{ audioContext: { currentTime: number }, bpm?: number = 120 }`. Owns `bpm: TempoParam` (with `now` bound to the context) and the anchor `{ beatAtAnchor: number, timeAtAnchor: number }` + `state: "stopped" | "playing" | "paused"` + `generation: number` + `positionAtAnchor: number`.
- [ ] Conversions (decision 2 for the not-playing case):
  - `beatToTime(beat)` = `origin + curve.timeToAdvance(origin, beat − beatAtAnchor)` where `origin = playing ? timeAtAnchor : now`
  - `timeToBeat(time)` = playing ? `beatAtAnchor + curve.beatsBetween(timeAtAnchor, time)` : `beatAtAnchor`
- [ ] Package-internal anchor writes used by Clock (each evaluates current beat/position first, then rewrites): `_start(atBeat = 0)`, `_pause()`, `_resume()`, `_stop()`, `_seek(beat)`. Jumps (`_start` with position change, `_seek`, `_stop`→`_start`) increment `generation`; `_pause`/`_resume` do not. `position` getter per decision 3.
- [ ] `addRuler(key, ruler)` — stores the ruler and creates a `current: Param<TPoint>` cell per slot (`timeline.rulers[key].current`); returns `this` typed with the accumulated ruler map (see Task 8 for the typing).
- [ ] Tests (fake context, no Clock needed): round-trip `beatToTime`/`timeToBeat` under constant tempo and across a scheduled step; pause freezes `timeToBeat` while `beatToTime` answers as-if-resumed-now; seek rewrites the anchor and bumps generation; position stopwatch across start/pause/resume; seek position per decision 3.

## Task 6: The four built-in rulers

**Files:** `src/rulers/{LinearBarRuler,CycleBarRuler,LinearTimeRuler,CycleTimeRuler}.ts`, `tests/rulers.test.ts`

Reading shapes per the spec's 2×2 table; `beatsPerBar` per decision 4.

- [ ] `LinearBarRuler({ numerator, denominator })` — point: `{ bar, beatInBar, numerator, denominator }`; window: point-at-window-start + `grid(division)` (division = steps **per bar**, step = beatsPerBar/division, origin 0) yielding `{ beat, time, index }` with `time = timeline.beatToTime(beat)`.
- [ ] `CycleBarRuler({ numerator, denominator, bars, from = 0 })` — region `[from, from + bars × beatsPerBar)` in axis beats. Point: `{ cycle, barInCycle, beatInBar, phase }` (`phase` ∈ [0,1)). Window adds `grid(division)` (division = steps **per cycle**) and `spans`: the window's beat range mapped to 1–2 sub-ranges in cycle coordinates, each `{ fromCycle, toCycle, toTime(cyclePos) }` where `toTime` closes over that pass's offset (spec: same cycle position converts differently per pass).
- [ ] `LinearTimeRuler()` — point/window: `{ seconds }` = `timeline.position` semantics (decision 3).
- [ ] `CycleTimeRuler({ seconds, from = 0 })` — point: `{ cycle, secondsInCycle, phase }`.
- [ ] Tests: bar/beatInBar values in 4/4 and 6/8; grid across a bar boundary; **cycle grid across the wrap** emits both sides with strictly increasing `time`; `spans` two-sub-range case and per-pass conversion difference; statelessness (same beat twice → identical reading).

## Task 8: Clock (tick loop, windows, transport) + addRuler typing

**Files:** `src/Clock.ts`, `tests/clock.test.ts`, `tests/typing.test-d.ts`

- [ ] Constructor `{ timeline, lookAhead = 0.1, tickInterval = 0.025, onTick, onMiss?, tickSource? }` (default `WorkerTickSource(tickInterval × 1000)`).
- [ ] Transport: `start({ atBeat }?)`, `pause()`, `stop()`, `seek(beat)` → timeline anchor writes; `state: Param<TransportState>`; every jump resets `previousWindowEndBeat` to the new position.
- [ ] Tick handler (the heart — implement exactly):

```
now = ctx.currentTime
refresh reactive surfaces: bpm._refresh(now); for each ruler slot: current.value = ruler.at(timeToBeat(now), timeline)
if state !== "playing": return
startBeat = previousWindowEndBeat
nowBeat   = timeline.timeToBeat(now)
if nowBeat > startBeat:                      // late: those beats are unschedulable
    onMiss?.({ gapStart: startBeat, gapEnd: nowBeat,
               gapDuration: now − timeline.beatToTime(startBeat) })
    startBeat = nowBeat
endBeat = timeline.timeToBeat(now + lookAhead)
if endBeat > startBeat:
    onTick(assembleWindow(startBeat, endBeat, now))     // includes generation, transport, ruler readings
previousWindowEndBeat = endBeat
```

- [ ] `assembleWindow` builds `{ time: { started, current, lookAheadEnd }, beat: { start, end }, generation, transport: { state, position }, rulers }` with each registered ruler's `read(coreWindow, timeline)`.
- [ ] Tests (fake context + `ManualTickSource`, fully deterministic): windows are contiguous and non-overlapping while playing; advancing the fake clock past a window end produces exactly one `onMiss` with the right gap and the next window starts at now-beat; pause → no windows, `current` still refreshes; resume → windows continue from the frozen beat with **no** generation bump; `seek` bumps generation and the next window starts at the target beat (beats may re-appear); tempo step mid-run changes window beat-width accordingly; `stop()` halts the tick source.
- [ ] `tests/typing.test-d.ts` (`expectTypeOf`): `addRuler("bar", new LinearBarRuler(...))` narrows `window.rulers.bar` to the bar window reading and `timeline.rulers.bar.current.value` to the point reading; unregistered keys are type errors. Implementation: `Timeline<R extends Record<string, Ruler<any, any>>>` with `addRuler` returning `Timeline<R & Record<K, T>>`; `Clock` generic over the timeline it consumes. If inference fights back, an explicit-generic escape hatch is acceptable — record the outcome against spec open question 2.
